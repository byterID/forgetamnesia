# Domain Docs

Как навыки должны читать доменную документацию этого репозитория. Раскладка — **single-context**, но пути нестандартные.

## Где что лежит

| Что | Путь | Отличие от умолчаний навыков |
|---|---|---|
| Глоссарий | `docs/CONTEXT.md` | не в корне репозитория |
| ADR | `docs/DECISIONS.md` | **один файл**, записи `ADR-NNN`; папки `docs/adr/` нет и создавать её не нужно |
| Спецификация | `docs/spec/*.md` | читать только раздел, на который ссылается тикет |

`CONTEXT-MAP.md` нет и не будет: один контекст.

## Перед работой

- Прочитать `docs/CONTEXT.md` (82 строки, целиком).
- В `docs/DECISIONS.md` — только ADR, затрагивающие область тикета (искать по `ADR-NNN` через grep).

## Словарь

Любое имя доменного понятия (заголовок тикета, имя теста, типа, функции) — по глоссарию: в коде колонка EN, в UI и документах — RU.
Синонимы не вводить. Особо: `Op` (операция журнала синхронизации) ≠ `Transaction` (операция с деньгами).
Понятия нет в глоссарии → либо это лишний термин, либо пробел: добавить строку в `docs/CONTEXT.md` и запись в `docs/DECISIONS.md`.

## Запись ADR

Новая запись — в конец `docs/DECISIONS.md`, следующий номер, формат из шапки файла:
`**ADR-NNN — Название** · статус · дата` + Контекст / Решение / Последствия (по 1–3 строки).
Статусы: `accepted` · `provisional` · `superseded by ADR-NNN`. Решение агента без согласования — всегда `provisional`.
Дополнение существующего ADR (итог спайка) — абзац «Дополнение <дата>» под записью, без нового номера.
