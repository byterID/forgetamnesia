# DECISIONS — архитектурные решения (ADR)

Статусы: `accepted` (согласовано с пользователем) · `provisional` (принято агентом, ждёт подтверждения в отчёте этапа) ·
`superseded by ADR-NNN`. Отступление от `accepted` — только после вопроса пользователю.

Формат записи: **ADR-NNN — Название** · статус · дата · Контекст / Решение / Последствия (по 1–3 строки).

**ADR-001 — PWA + Capacitor для Android** · accepted · 2026-11-16
Контекст: браузер не читает уведомления и не планирует локальные напоминания.
Решение: основной продукт — PWA; с M8 тот же код в Capacitor-оболочке для Android (уведомления, локальные напоминания, виджет, биометрия). iOS — PWA.
Последствия: платформенный код за интерфейсами в `src/services/platform/`.

**ADR-004 — Синхронизация журналами операций по устройствам** · accepted · 2026-11-16
Решение: `appDataFolder`; каждое устройство пишет только свои чанки; слияние last-writer-wins по полю с ключом `(hlc, deviceId)`; снимки + компактирование; UUID v7; tombstones.
Отвергнуто: общий JSON/SQLite с перезаписью (гонки, Drive не даёт атомарного compare-and-swap).
Детали — `spec/sync.md`.

**ADR-005 — Деньги в целых минимальных единицах** · accepted · 2026-11-16
`number` + `Number.isSafeInteger`; у актива `decimals ≤ 8` (крипта округляется до 8 знаков). Конвертация — `decimal.js`, банковское округление.

**ADR-006 — Курсы через USD-пивот, исторические** · accepted · 2026-11-16
Курс хранится как цена актива в USD на дату. Операция хранит курс к основной валюте на момент совершения. Ручная правка курса перекрывает API на дату.
Дополнение 2026-11-16 (accepted, подтверждено пользователем): операция хранит `usdPrice` своего актива на момент совершения, а не курс к основной валюте; сумма в основной валюте вычисляется через USD-цену основной валюты на ту же дату. Иначе смена основной валюты (ADR-007) обесценила бы сохранённые курсы.

**ADR-019 — Корректировка: положительная вне доходов, отрицательная — расход «Неучтённое»** · accepted · 2026-11-16
Контекст: в таблице пользователя «Корректировка баланса» входила в доход; исключение её целиком завышало бы запас прочности и ломало сверку с листом «Итоги».
Решение: положительная корректировка — не доход, отдельная строка аналитики; отрицательная — расход «Неучтённое», входит в `burnRate` и `savingsRate`.
Последствия: сверка с «Итогами по месяцам» (M4/M5) идёт по пересчитанной фикстуре, не по исходным цифрам таблицы.

**ADR-020 — Ликвидность, `availableNow`, `netWorth`** · provisional · 2026-11-16
Решение: соответствие вид счёта → ликвидность и формулы — в `CONTEXT.md`. Метрика «Доступно сейчас» названа `availableNow` (не путать со значением ликвидности `available`). `netWorth` — сумма балансов всех счетов; личные долги — отдельной строкой; инвестсчёт — по ручной оценке, иначе по вложенному.

**ADR-021 — Долг: заём и ожидаемое поступление** · provisional · 2026-11-16
Решение: `Debt.kind` = `loan` (вне доходов и расходов) или `expectedIncome` (доход при получении).

**ADR-022 — Обязательные и переменные расходы** · provisional · 2026-11-16
Решение: флаг `isMandatory` на категории расхода; `variableExpense` = расходы − обязательные − `isOneOff`. Категории «Крупные покупки» нет — только флаг `isOneOff` (исключает из `burnRate`, не из `savingsRate`).

**ADR-023 — Прогноз без двойного счёта** · provisional · 2026-11-16
Контекст: медиана расходов уже содержит регулярные платежи (аренда), повторное добавление плановых удваивает их.
Решение: сценарий `current` = медиана нетто-накоплений + только разовые плановые (`item`, `debt`, `probableExpense`, разовые `manual`). `runway` = `availableNow / burnRate` (простая формула для главной); симуляция «без дохода» называется `depletionDate`. Регулярный плановый доход (зарплата 14-го и аванс 28-го) — открытый вопрос M5, пока прогноз дохода берётся из медианы истории.

**ADR-024 — Курсовая разница, инвестиции, прочее** · provisional · 2026-11-16
Решение: `fxResult` — отдельная строка вне доходов и расходов; реализованная прибыль инвестсчёта — доход «Инвестиции», убыток — расход. `savingsRate` при нулевом доходе — «—», оценка «Очень плохо». Экземпляры `Obligation` и начисления процентов получают детерминированный id (источник + дата). Дата операции — локальный календарный день; границы месяцев по нему. `bank` и `card` различаются только полем «банк». Перевод в одном активе с разными суммами: разница — расход «Комиссии». `interestAccrual`: способ расчёта решается на M7.

**ADR-025 — Аренда жилья «(П)» и «(С)»** · provisional · 2026-11-16
Контекст: смысл букв неизвестен без пользователя.
Решение: при импорте обе колонки → категория «Жильё → Аренда» с тегами `П` и `С`; уточнить у пользователя при создании фикстур в M4. Открыты также: смысл колонок «Переводы», «Внешние переводы», «Долг» и листа «Состояние» (помесячные остатки?) — тоже на M4.

**ADR-026 — TypeScript закреплён на 6.0.x** · provisional · 2026-11-16
Контекст: `typescript-eslint` 8.x не поддерживает TypeScript 7 (линт падает при запуске); в TS 7 удалён `baseUrl`.
Решение: `typescript@~6.0`, алиас `@/` через `paths` с `./src/*`. Вернуться к TS ≥ 7.1, когда его поддержит `typescript-eslint`.

**ADR-027 — Обновление service worker: autoUpdate + skipWaiting** · provisional · 2026-11-16
Контекст: пользователь один, данные в IndexedDB, оболочка не хранит состояния; застрять на старой оболочке хуже, чем получить новую при следующей загрузке.
Решение: `registerType: 'autoUpdate'`, `skipWaiting` + `clientsClaim`, `cleanupOutdatedCaches`; навигация офлайн — fallback на `/index.html`. Принудительной перезагрузки открытой страницы нет — новая версия подхватывается при следующем открытии. Пересмотреть, если появятся несохранённые формы, которые нельзя терять.

**ADR-028 — Lighthouse CI против локальной production-сборки** · provisional · 2026-11-16
Контекст: замеры по URL Cloudflare Pages зависят от сети и CDN, результат недетерминирован.
Решение: `lhci autorun` поднимает `pnpm preview` на собранном `dist/`, 3 прогона, пресет `perf` (в Lighthouse нет категории PWA; устанавливаемость проверяют тест манифеста и e2e). Утверждения: Performance ≥ 0.95, LCP < 2000 мс, TBT < 200 мс. Размер: `size-limit` ≤ 200 KB gzip для `dist/assets/index-*.js`. В `index.html` лежит статичная оболочка (только имя бренда), чтобы FCP не ждал JS; Toaster подгружается лениво.

**ADR-029 — CSP и заголовки Cloudflare Pages (`public/_headers`)** · provisional · 2026-11-16
Решение: `default-src 'self'`; `script-src 'self' https://accounts.google.com/gsi/client` (без inline-скриптов); `frame-src https://accounts.google.com`; `connect-src 'self'` + `accounts.google.com`, `www.googleapis.com`, `oauth2.googleapis.com`; `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`. Дополнительно: `nosniff`, `Referrer-Policy`, `Permissions-Policy`, `COOP: same-origin-allow-popups` (нужен окну входа Google). `sw.js` и манифест — `no-cache`, `/assets/*` — `immutable`.
Компромисс: `style-src` содержит `'unsafe-inline'` (sonner вставляет `<style>`, оболочка в `index.html` — style-атрибут); скрипты при этом остаются строгими. Пересмотреть, когда появится nonce-механизм.
Открыто: хосты API курсов добавить в `connect-src` после спайка S3 (сейчас их нет, запросы к ним будут заблокированы). Расхождение в `nfr.md` N3 (только connect-src) этим решением закрыто.

**ADR-030 — `Money` несёт свой `Asset`; разбор ввода без догадок** · provisional · 2026-11-16
Решение: `Money = { amount, asset: { code, type, decimals } }` — актив вложен целиком, запись самодостаточна (синхронизации не нужен реестр активов). Активы равны при совпадении всех трёх полей. `decimals` фиата берётся из `Intl` (ISO 4217), крипты — ≤ 8. Разбор строки: единственный разделитель — десятичный; оба — десятичный последний; лишние знаки после запятой — ошибка, а не округление («1,000» для RUB отклоняется). Форматирование — `Intl` по точной десятичной строке, без float.
Последствия: все нарушения правил домена — `DomainError` с кодом; UI ветвится по `code`.

**ADR-031 — Курс и конвертация** · provisional · 2026-11-16
Решение: `usdPrice` — десятичная строка; USD всегда 1; нет курса на дату или раньше — ошибка `rate-missing` (будущий курс не подставляется). Точность `decimal.js` — 40 знаков, округление банковское. Итоги (`netWorth`, `availableNow`) конвертируются точно и округляются один раз.
Последствия: сумма округлённых строк по счетам может отличаться от итога на несколько минимальных единиц. Актив с нулевым балансом курса не требует.

**ADR-032 — Модель операции и баланса** · provisional · 2026-11-16
Решение: перевод хранит `sentUsdPrice` и `receivedUsdPrice`; `fxResult` и комиссия не хранятся, а вычисляются. Перевод в одном активе не может зачислить больше, чем списано. Баланс = начальный остаток + все операции счёта независимо от даты (`openingDate` пока справочное поле). В `availableNow` долг кредитки — только отрицательный баланс; переплата по кредитке и неиспользованный лимит в «доступно» не входят; переопределить ликвидность кредитки нельзя.
Отложено до M7: `netWorth` берёт баланс инвестсчёта, ручная оценка (`valuation`, ADR-020) пока не учитывается.

**ADR-033 — Стартовые категории с постоянными id** · provisional · 2026-11-16
Контекст: два устройства, засеявшие категории независимо, после синхронизации получили бы дубли.
Решение: id стартовых категорий детерминированы (`default:expense:housing:rent`); засев идемпотентен и не воскрешает удалённое. К набору F5 добавлена системная «Комиссии» (нужна ADR-024); «Комиссии» и «Неучтённое» удалить нельзя. Обязательные по умолчанию: Аренда, Коммуналка, Связь и подписки.

**ADR-034 — Слой хранения M1** · provisional · 2026-11-16
Решение: схема Dexie v2 — `accounts`, `transactions`, `categories`, `rates`. Удаление — надгробие `deletedAt`. Любая запись идёт через одну функцию `commit`, которая в той же Dexie-транзакции (по всем таблицам) вызывает `onWrite` — в M2 он станет источником `Op`; сбой `onWrite` откатывает запись. id курса — `asset:asOf:source`. Актив счёта, вид и родитель категории после создания не меняются; категорию с детьми удалить нельзя.

**ADR-035 — Формула капитала в таблице пользователя (допущение)** · provisional · 2026-11-16
Контекст: агенту запрещено читать `private/`, формула `Лист1!B9` неизвестна.
Решение: фикстура `tests/fixtures/account-state.json` построена по описанию `spec/import.md` I1; принято `итог = ΣAMD × курс + ΣRUB + ΣUSD × курс + ΣИИС`, колонка «Долг» в итог не входит (ADR-025).
Нужно от пользователя: подтвердить формулу B9 (входит ли «Долг», как учитывается «Крипта»).
