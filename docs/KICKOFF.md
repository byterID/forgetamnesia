# KICKOFF — промпт для первой сессии

**Перед стартом (делаешь ты):**
1. Создай публичный GitHub-репозиторий `forgetamnesia`, положи туда содержимое архива, закоммить в `main`.
2. Создай папку `private/` и положи туда свои xlsx (она в `.gitignore`).
3. Открой папку в VS Code, в Claude: `/model` → **Fable**, effort **high**.
4. Вставь текст ниже целиком.

---

```markdown
Привет. Это проект ForgetAmnesia. Прочитай CLAUDE.md (он уже в контексте), затем docs/PROGRESS.md.
Спецификацию целиком НЕ читай — только разделы, которые нужны на конкретном шаге.

1. Запусти навык `setup-matt-pocock-skills`: трекер — GitHub Issues этого репозитория, метки этапов
   `S1`…`S6`, `M0`…`M10`, а также `spike`, `needs-permission`, `provisional`;
   доменные документы — `docs/CONTEXT.md` и `docs/DECISIONS.md` (ADR лежат одним файлом).
2. Запусти навык `domain-modeling` по `docs/CONTEXT.md` (сверяя с `docs/spec/finance.md` и `docs/spec/analytics.md`):
   найди неоднозначные или противоречащие SPEC термины. Не правь документы молча — покажи мне список вопросов
   одним сообщением. Известные открытые: ADR-019 (корректировка), смысл «Аренда жилья (П)» и «(С)».
3. Перескажи мне в 10–15 пунктах, как ты понял систему, и перечисли места, где документы противоречат друг другу
   или оставляют решение открытым. Дождись моего ответа.
4. После моего подтверждения — навыком `to-tickets` создай тикеты для **W, S1, S2, S3 и M0** (только их).
   Каждый тикет самодостаточен: цель, файлы, критерии приёмки, ссылка на раздел spec/plan.
   Спайки, которые ходят в сеть, помечай `needs-permission`.
5. Обнови docs/PROGRESS.md и закончи сессию по протоколу контрольной точки из CLAUDE.md
   (без code-review — кода ещё нет), с напоминанием о /clear и модели для следующего шага (W: Sonnet · low).

**Правила, которые важнее скорости:**
- Сначала падающий тест, потом код. Всегда.
- Никаких запросов к Google API без моего разрешения в чате на конкретный спайк; только тестовый Google-аккаунт.
- Никаких записей в мой основной Google Drive/Calendar и деплоя на прод без моего подтверждения на конкретное действие.
- Не читать и не коммитить `private/`.
- Отступление от ADR — только после вопроса мне. Остальные решения — сам, со статусом `provisional`, списком в отчёте.
- В конце этапа: `code-review`, затем `thermo-nuclear-code-quality-review`, затем короткий отчёт мне:
  что работает, как проверить, что отложено, какие решения под вопросом.
- Если застрял на баге — навык `diagnosing-bugs`, а не перебор вариантов.
```

## Промпт для всех следующих сессий
После `/clear` и смены модели:

```
продолжай по PROGRESS.md
```

Если этап с тикетами ещё не заведён (M1+), агент сам начнёт с `to-tickets` для текущего этапа — это прописано в `docs/plan/<этап>.md` через «Тикеты-кандидаты».
