# SPEC — импорт (M4)

## I1. История из таблиц пользователя (ADR-016)
Файлы пользователя лежат в `private/` (не в git). Для тестов — обезличенные копии в `tests/fixtures/` с изменёнными суммами, та же структура.

**Таблица 1 — состояние счетов** (лист «Лист1»): строки — банки (Ardshin, Fast bank, Тбанк, Озон банк, ВТБ, Крипта),
колонки — валюты (AMD, Рубли, USD, «Запертые рубли ИИС»), курсы на дату в G/H, «Долг» в I.
Блок «Должны дать» (сумма, причина) → `Debt owedToMe`. Блок «Вероятные расходы» → плановые `probableExpense`.
→ Импорт как начальные остатки счетов (один счёт на пару банк+валюта; ИИС → `locked`; Крипта → `crypto` в USD-эквиваленте с просьбой уточнить монеты).

**Таблица 2 — помесячная история** (лист «Прибыль»: Зарплата(14), Аванс(28), Корректировка, Кешбэк, Внешние переводы;
лист «Траты»: Покупки, Переводы, Аренда (П), Аренда (С), Большая покупка; лист «Состояние»: Копилка 12%, Инвестиции Т/В, ИИС, Crypto, кредитка с лимитом).
→ Каждая ненулевая ячейка = операция-агрегат `importedAggregate: true`, дата — последний день месяца, валюта RUB.
«Большая покупка» → `isOneOff`. «Корректировка баланса» → `adjustment` (ADR-019). Агрегаты пишутся на счёт `importedHistory` (ADR-016). Лист «Итоги по месяцам» — только для проверки: аналитика должна дать те же норму сбережений и оценки, **пересчитанные по правилам ADR-019** (корректировка в доходе — исключение).

## I2. Универсальный импорт CSV/XLSX
1. Выбор файла → предпросмотр первых 20 строк.
2. Сопоставление колонок: дата, сумма (или приход/расход), валюта, описание, категория; формат даты и десятичный разделитель — автоопределение + ручная правка.
3. Выбор счёта.
4. Правила категоризации по подстроке описания (сохраняются и применяются в будущем).
5. **Дедупликация**: совпадение счёт + сумма + дата ±1 день + похожее описание → помечено «возможный дубль», по умолчанию не импортируется.
6. Импорт одной Dexie-транзакцией, кнопка «Отменить импорт» (все операции импорта помечены `importBatchId`).
Парсинг xlsx — SheetJS (`xlsx`), lazy chunk.
