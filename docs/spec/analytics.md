# SPEC — аналитика, прогноз, цели, советы (M5)

Все расчёты — чистые функции в `src/domain/analytics/`, покрыты тестами на фикстурах из таблиц пользователя.

## A1. Плановые операции
- Список «Планы»: будущие операции по датам, источник, вероятность.
- Обязательный платёж: название, сумма, счёт, категория, RRULE (ежемесячно N-го, ежегодно…), дата окончания.
  Разворачивается в плановые операции на горизонт 12 мес. (лениво, не хранить все экземпляры).
- Наступила дата → во «Входящих» «Оплачено?» → подтверждение в один тап.
- Вероятные расходы (поездка, переезд) — плановая с `source: probableExpense`, вероятность 0–1.

## A2. Метрики
- `burnRate` — медиана расходов за 3 последних **полных** месяца без `isOneOff`, включая «Неучтённое» (отрицательные `adjustment`, ADR-019). Рядом — среднее за 6.
  Если истории < 3 мес. — использовать что есть + метка «мало данных».
- `runway = availableNow / burnRate` (месяцев, 1 знак). Симуляция «без дохода» даёт отдельную `depletionDate` (ADR-023).
- `savingsRate` за месяц и оценка (пороги из таблицы пользователя, настраиваемые):

| savingsRate | Оценка |
|---|---|
| < −10% | Очень плохо |
| < 0% | Не хорошо |
| < 10% | Слабое накопление |
| < 20% | Минимально нормально |
| < 50% | Хорошо |
| ≥ 50% | Очень хорошо |

- Доля обязательных расходов = обязательные / доход.

## A3. Графики (Recharts, lazy chunk)
1. Доход vs расход по месяцам (столбцы) + линия нормы сбережений (%), цвет оценки.
2. Расходы по категориям за месяц (горизонтальные столбцы), сравнение с медианой 3 мес.
3. Капитал во времени (факт) + прогноз пунктиром до 12 мес. по сценариям.
4. Режим «без дохода»: таяние `available` при `burnRate` + плановых; дата обнуления.

## A4. Советы (правила, не LLM)
Каждый совет: заголовок, одно предложение-обоснование с числами, действие.
- Обязательные > `fixedShareThreshold` (50%) дохода → «Обязательные расходы съедают X% дохода — сократить их сложно, ищи доп. доход».
- Категория выросла > `categoryGrowthThreshold` (25%) к медиане и > 5% расходов → «Y выросли на Z% — это −N к цели в месяц».
- `savingsRate < 0` два месяца подряд → «Тратишь больше, чем зарабатываешь; запас прочности M мес.».
- `runway < 3` → предупреждение на главной.
Пороги — в настройках.

## A5. Цели
- Цель: название, сумма, актив, дедлайн (необяз.), приоритет, иконка.
- Резерв: вручную («отложить N») или авто — свободный остаток месяца распределяется по приоритетам (настройка).
- Прогноз даты достижения в сценариях:
  `current` (медиана нетто-накоплений 3 мес. + только разовые плановые, ADR-023), `cutVariable` (−X% переменных, X в UI), `extraIncome` (+N в месяц, N в UI).
- Если дедлайн задан: «нужно откладывать N в месяц; сейчас — M».
- Калькулятор ипотеки/кредита — M9.
