# CONTEXT — глоссарий предметной области

Один термин — одно значение. Код использует английское имя, UI и документы — русское.
Новый термин или смена смысла → запись в `DECISIONS.md`.

## Деньги

| RU | EN (код) | Определение |
|---|---|---|
| Основная валюта | `baseCurrency` | Валюта, в которой показываются итоги. По умолчанию RUB, меняется в настройках. |
| Актив | `Asset` | Валюта или монета: код, тип (`fiat`/`crypto`), число знаков `decimals` (≤ 8). |
| Сумма | `Money` | `{ amount: integer minor units, asset }`. Никогда не float. |
| Курс | `Rate` | Цена актива в USD на дату (`asOf`), источник `api`/`manual`. Кросс-курс считается через USD. |
| Счёт | `Account` | Место хранения денег одного актива. Вид — `AccountKind`. |
| Позиция | `Position` | Счёт вместе с его текущим балансом (начальный остаток + операции). |
| База отчёта | `ReportingBasis` | В чём считаются итоги: основная валюта, набор курсов и дата. Не путать с `valuation`. |
| Вид счёта | `AccountKind` | `cash`, `bank`, `card`, `credit`, `savings` (с процентом), `locked` (ИИС, депозит без снятия), `investment`, `crypto`. |
| Ликвидность | `liquidity` | `available` / `locked` / `volatile`. Выводится из вида счёта, можно переопределить: `cash`, `bank`, `card`, `savings` → `available`; `locked` → `locked`; `investment`, `crypto` → `volatile`; `credit` — вне ликвидности (долг учитывается отдельно). |
| Операция | `Transaction` | Фактическое движение денег. Тип — `TransactionType`. |
| Тип операции | `TransactionType` | `expense`, `income`, `transfer`, `adjustment`. |
| Перевод | `transfer` | Между своими счетами. Не доход и не расход. Если активы разные — **обмен** (`exchange`), хранит обе суммы. |
| Курсовая разница | `fxResult` | Разница между фактическим курсом обмена и рыночным на дату. Отдельная строка аналитики, вне доходов и расходов. |
| Корректировка | `adjustment` | Создаётся **сверкой баланса**. Положительная — не доход, отдельная строка аналитики. Отрицательная — расход «Неучтённое» (входит в `burnRate` и `savingsRate`). Хранится как положительная сумма + направление. |
| Обязательная категория | `isMandatory` | Флаг категории расхода: траты в ней — обязательные (аренда, коммуналка, связь). |
| Переменный расход | `variableExpense` | Расход, не обязательный и не `isOneOff`. Его сокращает сценарий `cutVariable`. |
| Импортированная история | `importedHistory` | Системный счёт для `importedAggregate`-операций из xlsx; не входит в капитал и «доступно». |
| Сверка баланса | `reconciliation` | Пользователь вводит реальный остаток → приложение создаёт корректировку на разницу. |
| Разовая крупная | `isOneOff` | Флаг расхода (колонка «Большая покупка»); исключается только из `burnRate`, в `savingsRate` остаётся. Отдельной категории «Крупные покупки» нет. |
| Категория | `Category` | Двухуровневая (`parentId`). Отдельные деревья для доходов и расходов. |
| Тег | `Tag` | Свободная метка поперёк категорий («Китай-2026»). |
| Шаблон траты | `TransactionTemplate` | Сохранённая трата для ввода одним тапом. |

## Инвестиции и долги

| RU | EN | Определение |
|---|---|---|
| Инвестсчёт | `investment` account | Деньги на него — перевод. Прибыль не признаётся, пока деньги не выведены. |
| Вывод с инвестсчёта | `investmentWithdrawal` | Отдельная форма: перевод обратно + реализованная прибыль/убыток = вывод − вложенный остаток. Прибыль — доход «Инвестиции», убыток — расход. |
| Оценка | `valuation` | Ручная текущая стоимость инвестсчёта. В капитале используется вместо вложенной суммы; не прибыль. |
| Кредитная карта | `credit` account | Баланс ≤ 0 = долг; `creditLimit`; `paymentDay` → плановая операция. Неиспользованный лимит в «доступно» не входит. |
| Долг / ожидаемое поступление | `Debt` | `direction: 'owedToMe' \| 'iOwe'`, `kind: 'loan' \| 'expectedIncome'`, сумма, ожидаемая дата, `probability` (0–1). `loan` при получении/возврате — вне доходов и расходов; `expectedIncome` при получении — доход. Личные долги в капитал не входят, показываются отдельной строкой. |
| Начисление процентов | `interestAccrual` | Для `savings`: ставка годовых, раз в месяц создаёт доход. |

## Планирование и прогноз

| RU | EN | Определение |
|---|---|---|
| Плановая операция | `PlannedOperation` | Будущее движение денег, ещё не случившееся. **Центральная сущность прогноза.** Источник — `source`. |
| Источник плановой | `source` | `obligation`, `item` (событие/задача), `debt`, `probableExpense`, `creditPayment`, `manual`. |
| Обязательный платёж | `Obligation` | Повторяющаяся плановая операция (аренда, подписки) по RRULE. Помечает расход как обязательный. |
| Подтверждение | `confirm` | Плановая → фактическая операция (сумма и счёт могут отличаться). Плановая получает `status: done` и ссылку. |
| Цель | `Goal` | Сумма, актив, необязательный дедлайн, приоритет. |
| Резерв | `Reservation` | Виртуально отложенная под цель часть денег. Деньги остаются на счетах. |
| Капитал | `netWorth` | Сумма балансов всех счетов в основной валюте (включая locked и volatile; отрицательный баланс кредитки уже уменьшает сумму). Без `importedHistory` и личных долгов. |
| Доступно сейчас | `availableNow` | Сумма счетов с ликвидностью `available` минус долг кредиток минус резервы целей. (Не путать со значением ликвидности `available`.) |
| Средний расход | `burnRate` | Медиана месячных расходов за 3 полных месяца без `isOneOff`, включая «Неучтённое». Рядом — среднее за 6. |
| Запас прочности | `runway` | `availableNow / burnRate`, в месяцах. Простая формула для главной. |
| Дата обнуления | `depletionDate` | Результат симуляции «без дохода» с плановыми операциями; не равна `runway`. |
| Норма сбережений | `savingsRate` | `(доход − расход) / доход` за месяц. Оценка по порогам (spec/analytics.md). |
| Сценарий | `Scenario` | `current`, `cutVariable` (−X% переменных), `extraIncome` (+N в месяц), `noIncome`. |

## Календарь и задачи

| RU | EN | Определение |
|---|---|---|
| Запись | `Item` | Событие или задача. `kind: 'event' | 'task'`. |
| Событие | `event` | Есть точное время начала (и конца). |
| Задача | `task` | Есть дедлайн или его нет. |
| Горизонт | `Horizon` | **Вычисляется** из дедлайна: `overdue`, `today`, `tomorrow`, `week`, `month`, `later`, `someday` (нет даты = «на подумать»). |
| Срочно | `urgent` | Флаг, независимый от горизонта. |
| Ожидаемая трата | `expectedCost` | Поле записи → порождает плановую операцию с `source: 'item'`. |
| Подготовка | `prepTask` | Дочерняя задача «купить до…»; плановая трата переезжает на её дату. |
| Входящие | `Inbox` | Неразобранные записи: черновики быстрой записи и распознанные уведомления. |
| Черновик | `CaptureDraft` | Сырой текст быстрой записи + результат разбора. Сохраняется до разбора. |
| Правило уведомлений | `NotificationRule` | Шаблон для пакета Android-приложения банка, созданный «по примеру». |

## Синхронизация

| RU | EN | Определение |
|---|---|---|
| Устройство | `Device` | Установка приложения; `deviceId` (UUID v7) в IndexedDB. |
| Операция журнала | `Op` | Атомарное изменение сущности. Не путать с `Transaction`! |
| Журнал | `OpLog` | Упорядоченные `Op` одного устройства. Пишет только владелец. |
| Чанк | `chunk` | Файл журнала `ops-<deviceId>-<firstSeq>.jsonl` в Drive. |
| HLC | `hlc` | Hybrid Logical Clock — метка времени операции, устойчивая к расхождению часов. |
| Снимок | `Snapshot` | Полное состояние + вектор `deviceId → lastSeq`, который он покрывает. |
| Конверт | `Envelope` | Обёртка файла: `{ v, enc: 'none' | 'aes-gcm', payload }`. |
| Надгробие | `tombstone` | Удаление = пометка `deletedAt`, физически не стирается. |
