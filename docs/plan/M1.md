# M1 — Доменное ядро · Fable · high · ветка `m1-domain-core`

**Цель**: вся финансовая логика базового уровня — чистый TS в `src/domain/`, без React/Dexie/сети, покрыта тестами.
**Читать**: `CONTEXT.md` (разделы «Деньги»), `spec/finance.md` F2–F5, ADR-005/006/007/019.

## Тикеты-кандидаты
1. `Money` и `Asset`: создание из строки ввода («5 000,50»), форматирование через `Intl`, сложение/вычитание только одного актива, ошибки на смешение; округление банковское.
2. `Rate` и конвертация через USD-пивот (`decimal.js`); выбор курса на дату (ближайший прошлый, ручной приоритетнее).
3. `Account` со всеми `AccountKind` и выводом `liquidity` (поля M7 — как типы, без поведения).
4. `Transaction`: expense/income/transfer(включая exchange + `fxResult`)/adjustment; инварианты (сумма > 0, активы совпадают со счетами).
5. Баланс счёта = начальный остаток + Σ операций; `netWorth`, `available` в основной валюте (без резервов — они в M5).
6. Сверка баланса → корректировка.
7. Категории: дерево двух уровней, стартовый набор из `spec/finance.md` F5.
8. Dexie-схема v2 и репозитории для этих сущностей (тонкий слой; каждая запись — через функцию, которая в M2 начнёт порождать `Op`). Заложить точку расширения `onWrite`.
9. Фикстуры: обезличенное состояние счетов из таблицы пользователя → тест «капитал совпадает с формулой таблицы».

## Готово, когда
- 100% веток в `src/domain/money` и `src/domain/fx` покрыты; property-тесты (fast-check): конвертация туда-обратно, сумма балансов инвариантна к порядку операций.
- Тест на фикстуре таблицы даёт тот же итог, что `Лист1!B9` (с поправкой на обезличивание).
