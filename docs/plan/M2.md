# M2 — Синхронизация · Fable · extra · ветка `m2-sync`

**Цель**: надёжная синхронизация нескольких устройств через `appDataFolder` по `spec/sync.md`. Ни одной потерянной записи.
**Читать**: `spec/sync.md` целиком, ADR-004 (с дополнениями S1/S2), ADR-014.

## Тикеты-кандидаты
1. HLC: генерация, приём чужих меток, сериализация, сравнение. Property-тесты.
2. `Op` и журнал: репозитории M1 пишут `Op` в той же Dexie-транзакции; `seq` без пропусков; `pushedSeq`.
3. Слияние: применение операций, LWW по полю, tombstones, неизвестные поля сохраняются; идемпотентность. Property-тест «порядок не важен».
4. Конверт `{v, enc, payload}` (enc = 'none'), сериализация JSONL.
5. Drive-адаптер за интерфейсом `RemoteStore` (list/get/put/delete/changes); реализация на Drive REST + фейк в памяти с инъекцией сбоев (обрывы, 401, 429, 5xx, медленные ответы).
6. Google-auth сервис: GIS token client, токен в памяти, тихое обновление, событие «нужен вход».
7. Цикл синхронизации: триггеры, Web Locks, BroadcastChannel, pull → apply → push, backoff.
8. Снимки и компактирование; восстановление нового устройства из снимка.
9. Защиты из таблицы угроз S5 (#9, #11, #12, #13) + JSON-экспорт/импорт как аварийный бэкап.
10. Индикатор синхронизации в шапке (S6 в spec).

## Готово, когда
- Симуляция: 3 фейковых устройства × 1000 случайных операций × случайные сбои → состояния идентичны (seed фиксируется в логе при падении).
- Ручная проверка на тестовом аккаунте: два браузерных профиля + телефон, офлайн-правки на обоих, затем онлайн — без потерь.
- Каждая строка таблицы угроз `spec/sync.md` S5 ссылается на тест или ручной сценарий в отчёте.
